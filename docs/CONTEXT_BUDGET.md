# Контекст, кэш и бесплатные токены

Даже бесплатный вызов расходует время и общую квоту. Экономия оценивается на принятом результате, включая повторы и проверку.

## До и во время задания

- Малый контракт, разрешённые файлы, известный API и критерий остановки.
- Короткий постоянный AGENTS.md; переменные факты и конкретная ошибка — в задании.
- Точечное чтение, ограниченные логи, минимум MCP. Не прикладывать весь репозиторий и бинарные ассеты.
- Один исполнитель для простого изменения. Параллельные процессы полезны только для независимых задач и доступной общей квоты.
- Один осмысленный повтор с новой диагностикой; затем смена маршрута или уменьшение задачи.
- Короткая сессия и передача состояния в файле. Сжатие истории не заменяет память проекта.

Для точной замены проверен режим JSON-патча без инструментов. В LUM-058 модель получила два литерала и конкретную причину: 1018 input, 195 output, 637 reasoning; один шаг. Это отдельное измерение, не контролируемый бенчмарк против широкой задачи.

## Кэш

Считать кэш свойством конкретного провайдера, модели и тарифа. Не обещать его бесплатность или исключение из квот без актуальной документации и счётчиков. Если кэш подтверждён, держать устойчивый префикс, а переменные данные добавлять позже. Не увеличивать ненужный контекст ради порога кэширования.

Проверять [OpenCode models](https://dev.opencode.ai/v2/docs/models/), условия [OpenRouter](https://openrouter.ai/docs/features/prompt-caching) и [лимиты Groq](https://console.groq.com/docs/rate-limits). Условия могут измениться.

## Учёт

Фиксировать отдельно input, output, reasoning, cache.read/write, число шагов, время, доступность, повторы и результат. Не складывать поля без знания их семантики. `cost` из OpenCode — локальная оценка, которая сама по себе не доказывает списание провайдера.

Сырые измерения без prompts/ключей:

- [20.10: весь день Lumi, 40 сессий и 274 шага](benchmarks/lumi-20261020-usage.json).
- [21.10: шесть сессий, 12 шагов](benchmarks/lumi-20261021-usage.json).
- [23.10: одна сессия, один шаг](benchmarks/lumi-20261023-usage.json).

Это разные объёмы работ, поэтому прямое сравнение не является доказательством коэффициента экономии. Нужный следующий этап — сопоставимые задачи на одном base SHA с учётом всего цикла до приёмки.
