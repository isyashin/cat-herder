# OpenCode: рабочая справка

Проверенная версия пилотов — **v2.0.30**, последняя локальная проверка 23.10.2026. Перед обновлением сверять [команды](https://dev.opencode.ai/v2/docs/cli/commands/), [схему](https://dev.opencode.ai/v2/docs/config/), [agents](https://dev.opencode.ai/v2/docs/agents/) и [permissions](https://dev.opencode.ai/v2/docs/permissions/). V1 и V2 используют разные поля.

## Подготовка

Провайдера подключают локально через OpenCode; auth-файлы не копируются в проект. Выбрать точный ID из каталога и проверить бесплатность у аккаунта. Суффикс free и наличие модели в списке не гарантируют остаток квоты.

```powershell
opencode --version
opencode run --help
opencode models --standalone
opencode auth list
```

Не публиковать сырой вывод эффективной конфигурации: он может содержать секреты. Не отключать TLS при ошибке сертификата; выяснить цепочку доверия и настройки среды. Сертификаты/пути конкретной машины в этот репозиторий не входят.

## Два режима маленького задания

- [Редактор файлов](../examples/opencode.editor.jsonc): read/edit, запрет execute/shell и внешних каталогов, короткий system и предел шагов.
- [Ответ JSON-патчем](../examples/opencode.json-patch.jsonc): инструменты запрещены, модель возвращает артефакт. Подходит, когда координатор уже установил точное изменение.

Выбранный пример копируется в `opencode.jsonc` отдельного клона. Эти настройки проверены с v2.0.30; они не создают [ОС-изоляцию](ISOLATION.md).

Пример вызова из подготовленного клона приложения, после настройки прав и выбора доступной бесплатной модели:

```powershell
$model = 'groq/openai/gpt-oss-120b'
$taskPrompt = Get-Content -LiteralPath '<TASK_PROMPT_FILE>' -Raw
opencode run --standalone --agent build --model $model --title TASK-001 $taskPrompt
```

Модель здесь — исторически проверенный пример, а не универсальный бесплатный маршрут. Для нужного контекста добавлять только точечные `--file`. `agents.build.system` заменяет базовый provider prompt; инструкции проекта продолжают действовать. На последнем `steps` инструменты могут быть сняты, поэтому слишком малый предел мешает записать код.

## Наблюдение и приёмка

Во время работы смотреть stdout/stderr: чтения, записи, отказы доступа, ошибки API, 429 и интервалы без прогресса. Долгое рассуждение, отсутствие разрешения и неработающий инструмент требуют разных решений.

После работы проверять файлы, а не только exit. Для JSON-патча сначала проверить все пути по allowlist, фактическое число совпадений old и весь пакет; затем применить в отдельной копии и выполнить приёмку. Не применять такой ответ произвольным shell-кодом. [Пример формата](../examples/patch.json).

## Сессии и счётчики

```powershell
opencode session list --max-count 20 --format json
opencode stats --standalone --days 0 --project . --full --json --limit 50
```

Использовать короткую сессию для одной задачи. `--continue`, `--session` и `--fork` требуют понимания того, какой контекст переносится. Экспорт сессии даже после sanitize нужно просмотреть перед публикацией. [Бюджет контекста](CONTEXT_BUDGET.md).
