# Правила Cat Herder

Cat Herder — отдельный проект координатора. Приложения, над которыми он работает, живут в собственных соседних Git-репозиториях.

- Руководитель отвечает за требования, архитектуру, декомпозицию, маршрутизацию моделей, ревью и интеграцию. Код исполняемых средств проекта поручается агентам через OpenCode на подтверждённых бесплатных маршрутах; документацию и независимые проверки ведёт координатор.
- Перед работой читать только нужные документы: [процесс](docs/PROCESS.md), [OpenCode](docs/OPENCODE.md), [модели](docs/MODELS.md), [изоляция](docs/ISOLATION.md), [состояние](docs/STATUS.md).
- Каждый кодовый контракт фиксирует исходный commit, разрешённые пути, интерфейсы, критерии приёмки, проверки и предел попыток. Агент получает отдельную копию; ветка или clone сами по себе не ограничивают права ОС.
- Оплата, платный fallback и изменение тарифов — по отдельному решению пользователя. Каталог и условия бесплатного маршрута сверять перед назначением задачи, версию/схему OpenCode — перед новой фазой и после обновления CLI.
- Наблюдать фактические stdout/stderr и diff. `exit 0` и самоотчёт модели не являются приёмкой. Ошибку квоты не смешивать с оценкой качества.
- Изменения интегрировать только после независимой проверки. Сохранять факты в журнале модели; токены, reasoning и cache записывать раздельно, не угадывая семантику счётчиков.
- При активной работе держать явные «в работе / в очереди / принято». Новое пожелание добавлять в очередь, не перенаправляя исполнителя без причины или изменения приоритета пользователем.
- Минимизировать контекст, MCP и число попыток. Для маленького точного изменения допустим JSON-патч без инструментов; координатор проверяет пути и точное число совпадений до применения.
- В публичный Git не помещать ключи, auth-файлы, `.env`, сырой вывод конфигурации, полные сессии и рабочие логи. Снимки кабинета, индивидуальные настройки лимитов и пути профиля остаются в локальных заметках; наблюдения из ошибок экспериментальных задач публикуются обезличенно и с датой.
- Исторический Windows-runner в `reference/` не запускать как готовую защиту. При реализации переносимого runner сначала закрыть ограничения из ISOLATION.md и проверить их на временных репозиториях.
- Основная Desktop/OpenAI-сессия остаётся на настроенном провайдере. Из неё не запускать нативные `kimi_*`: они наследуют провайдера родителя. По явному запросу Kimi используется отдельный Codex CLI с `codex --profile kimi`; платные маршруты не включаются автоматически.
